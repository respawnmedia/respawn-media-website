How it works

A quick guide to the asset library and how it bypasses the chat-upload zip issue.

1 · Why this exists

Chat attachments rejecting your zip is a payload-size problem on the upload pipeline, not something I can fix from inside the chat. Instead, this page gives you a place to store assets locally in the browser itself, which has a much higher capacity (typically 1–10 GB depending on your browser).

2 · Drop files

Open the Upload tab, drop your photos and videos. Each file is saved as a Blob in IndexedDB under the database respawn-assets, with metadata (name, tag, note, dimensions, etc.) stored alongside.

3 · Tag for the website

Click any asset and assign a tag like case/sree/hero, case/avias/gallery, or logos/matiks. The main website can then read assets by tag.

4 · Use from the site

Your site reads assets via window.RespawnAssets.get(tag) which returns an object URL from the locally stored Blob. A snippet you can paste into the site:

// All by tag prefix:
const heroes = await RespawnAssets.byPrefix('case/sree/');
// One specific:
const url = await RespawnAssets.firstUrl('case/sree/hero');
img.src = url;

5 · Persistence

Files survive page reloads and computer restarts. They live only in this browser, on this device. Use Storage → Export to back up. Clearing browser data will delete them, so export periodically if these are originals.
